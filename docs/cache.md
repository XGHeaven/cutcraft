# 缓存管理

缓存管理器统一负责项目 `cache/` 下的命名空间、文件/文件组发布、最近访问记录、跨进程使用中保护和容量淘汰。调用方只决定缓存键及内容是否仍有效；工程协议、素材时间、渲染结果和 revision 不因此改变。

```sh
cutcraft -p film.cut cache status
cutcraft -p film.cut cache clean
cutcraft -p film.cut cache clean --dry-run
```

`status` 报告各类缓存字节数、条目数、使用中/受保护条目及统一容量限制。`clean` 删除所有当前可回收的已知缓存；全局 `--dry-run` 只预估，不删除数据。命令通过 Store 读取真实工程快照，不修改工程、历史或编辑者信息。打开中的工程沿用 ApplicationHost 路由。

统一默认预算为每工程 1 GiB。解码窗口和浏览器播放各有 512 MiB 子预算；PNG/缩略图/波形共享 64 MiB、256 条，文字和拼图各 64 MiB、256 条。区间/整段 MP4 和暂存数据也纳入总预算；单次浏览器播放另保留 128 MiB 取消阈值。命中刷新访问时间，容量清理按最近使用顺序淘汰。预算是可回收数据的目标限制：使用中数据、当前刚生成的结果以及受素材引用保护的数据不会被强行删除，可暂时超限，统计明确显示。

条目使用 OS 文件锁跨 CLI/服务进程保护，解码窗口的 raw/pts/ready 作为整体管理；进程退出后锁自动释放，不能删除锁文件来解除占用。缓存元数据锁与工程编辑锁相互独立。临时工作目录也持有租约，正常退出自动移除，异常退出遗留目录可在后续清理回收。缓存命中不更新工程文件。

只管理已知缓存目录和文件命名；未知文件以及符号链接保留，不沿符号链接递归删除。原始素材（包括当前工程引用的缓存路径）、assets、output、.cutcraft 恢复数据和旧 working 目录不作为可删除缓存。`.manager` 下稳定的锁文件是协调数据，不计入可回收条目，也不通过 clean 删除。

现有缓存按已知布局接管，无需改写工程。仅在发布、浏览器任务结束或显式清理时回收，不运行后台定时器。单帧/缩略图/波形/文字沿用原有命中条件；区间和整段 MP4、拼图仍每次生成，不借此改变渲染语义。内存解码窗口及图片序列缓存仍随渲染会话释放，其容量策略集中于缓存模块；磁盘总预算不等同于进程内存上限。

自动淘汰通过 Store 读取最新快照；遇到工程编辑锁时暂缓，避免依据旧 revision 删除新导入的素材。仅传入内存工程、没有 cutcraft.json 的库调用仍可使用缓存，但不执行自动淘汰。`status` 与 `--dry-run` 可能建立协调锁文件，不改变缓存访问顺序、缓存内容或工程。统计只覆盖已识别的条目，不代表 `cache/` 内所有未知文件的实际磁盘占用。完成的浏览器播放缓存可被淘汰；客户端沿用过期后从当前时间重启播放的行为。
