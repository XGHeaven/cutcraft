# 媒体环境诊断

```sh
cutcraft doctor
cutcraft doctor --timeout 20
```

`doctor` 无需工程，总是在当前 CLI 进程执行，不转发到已打开工程的编辑器服务。它通过与媒体命令相同的可执行文件查找方式启动 `ffmpeg` / `ffprobe`，不下载、安装或修改环境。修改 PATH 后需重启已经运行的编辑器服务，当前 CLI 的诊断不能代表旧服务进程的环境。

检查项包括：

- FFmpeg / ffprobe 能否启动及版本。已知数字版本要求 6.1+；无法识别开发构建版本时警告，并继续能力和实际运行检查。
- Cutcraft 使用的编码器、核心音视频滤镜，以及文件形式滤镜图参数。
- 在系统临时目录生成极小的测试输入，实际执行文字 PNG、FFV1/PCM 无损中间文件、H.264/AAC MP4 编码，再由 ffprobe 检查 MP4 流信息，并解码视频和音频。临时目录随诊断结束清理。

stdout 始终输出一份诊断 JSON，包含 `ok`、CLI 版本、平台、检查列表和汇总。每项包含 `id`、`status`（passed/failed/warning/skipped）、说明和必要的修复建议；能力缺失会列出具体名称。`pathCandidates` 仅列出 PATH 中发现的同名文件，帮助识别多版本冲突，不保证就是操作系统最终选择的路径。

全部必需检查通过时退出 0；任一失败退出 1，但仍在 stdout 返回完整报告，不因缺少一个工具而停止检查另一个。warning 不单独导致失败，依赖失败的后续检查标为 skipped。命令参数错误遵循普通 CLI 错误行为；诊断基础设施异常（如无法创建临时目录）使用现有 stderr 错误 JSON。

`--timeout` 是每个外部检查的超时秒数，默认 10，范围 1–120。超时停止并回收进程，报告 `MEDIA_TOOL_TIMEOUT`。不同检查分别计时，不代表整次诊断的总时限。

此功能验证当前基础媒体路径，不保证所有素材编码、字体字形、硬件加速或项目内容都能渲染。检查文字时使用 FFmpeg 默认字体；指定苹方等字体的具体项目仍应执行 `validate --level media` 和预览。
